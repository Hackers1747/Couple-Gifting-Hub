# Architecture

## Monorepo layout

pnpm workspace (`pnpm-workspace.yaml`), packages under `artifacts/*`, `lib/*`,
`lib/integrations/*`, and `scripts`. Node.js 24, TypeScript 5.9, strict per-package
`tsc --build` via `tsconfig.base.json` / `tsconfig.json`.

```
artifacts/
  api-server/       Express 5 backend (the product's only backend)
  heartdrop/        React 19 + Vite frontend — the actual HeartDrop product UI
  mockup-sandbox/   Separate Vite/React app for previewing UI mockups
                     (has its own mockupPreviewPlugin.ts) — not part of the
                     shipped product, a Replit-provided design-preview tool.
lib/
  db/               Drizzle ORM + node-postgres, schema currently EMPTY
  api-spec/         OpenAPI 3.1 spec (openapi.yaml) + Orval codegen config
  api-zod/          Zod schemas generated from the OpenAPI spec (lib/api-zod/src/generated)
  api-client-react/ React Query hooks generated from the OpenAPI spec
scripts/
  post-merge.sh     pnpm install --frozen-lockfile && pnpm --filter db push
```

## Request flow

`heartdrop` (frontend) → same-origin `fetch('/api/...')` calls → `api-server`
(`artifacts/api-server/src/app.ts` mounts everything under `/api`) → in-memory
data structures inside each route module (see [api.md](./api.md)).

The frontend does **not** use the generated `@workspace/api-client-react` hooks
for any of the product routes — `src/hooks/useCardData.ts` and every page under
`src/pages/` call `fetch()` directly against relative `/api/...` paths. The
generated client only has typed coverage for `/healthz`, since that's the only
endpoint in `lib/api-spec/openapi.yaml`.

## Data storage: not yet wired to a real database

Two separate, unfinished paths exist for persistence, and neither is connected to
any route yet:

1. **`@workspace/db`** (`lib/db`) — Drizzle ORM over `node-postgres`, reads
   `DATABASE_URL` and throws immediately if it's unset (`lib/db/src/index.ts`).
   `lib/db/src/schema/index.ts` is an empty placeholder (no tables exported).
   It's listed as a dependency of `artifacts/api-server` (`package.json`) but is
   not imported anywhere in `artifacts/api-server/src` as of this scan.
2. **Supabase** — `artifacts/api-server/src/lib/supabase.ts` reads `SUPABASE_URL`
   and `SUPABASE_SERVICE_ROLE_KEY` and throws if either is unset, but only
   re-exports the raw strings (no Supabase client is constructed there). It is
   also not imported by any route.

All actual runtime state — cards, users, love-drop schedules, tracking events,
payment records — lives in plain in-memory arrays/objects inside the route
modules themselves (`routes/cards.ts`, `routes/track.ts`, `routes/payment.ts`,
`cron.ts`). Every one of these has inline `// TODO (Supabase): replace with ...`
comments sketching the intended Supabase queries. **This means all data is lost
on every server restart**, and horizontal scaling (multiple server instances)
would give inconsistent results, since state isn't shared.

If you wire up persistence, decide first whether you're standardizing on
`@workspace/db` (Drizzle/Postgres) or Supabase's client SDK — the codebase
currently has scaffolding for both but a working implementation of neither.

## Frontend build

`artifacts/heartdrop` is a Vite + React 19 SPA using `wouter` for routing
(`src/App.tsx`), Tailwind v4, shadcn/Radix UI components, TanStack Query (query
client is instantiated but not actually used for data-fetching — see above),
Framer Motion for the multi-step `Create` flow animations.

`vite.config.ts` requires `PORT` and `BASE_PATH` env vars at build/dev time (throws
if either is missing) and injects `RAZORPAY_KEY_ID` into the client bundle as
`import.meta.env.VITE_RAZORPAY_KEY_ID`.

## Deployment

`.replit` configures `autoscale` deployment (`[deployment] deploymentTarget =
"autoscale"`), with a post-build step that runs `pnpm store prune`. Four ports
are declared (8080, 8081→80, 8082→3002, 19763→3000) — not all of these were
traced to a specific service in this scan; treat unfamiliar ones as `Unknown`
until confirmed.

`[postMerge]` runs `scripts/post-merge.sh`, which does `pnpm install
--frozen-lockfile` then `pnpm --filter db push` (a Drizzle schema push) — this
runs on every merge even though the schema is currently empty.
