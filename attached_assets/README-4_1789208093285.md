# HeartDrop — Documentation

This is a pnpm monorepo for **HeartDrop** (product domain: `heartdrop.in`), a couples'
digital-gifting app: a sender picks an "experience" (sorry / proposal / birthday /
anniversary / puzzle / love letter / heartpage), writes or AI-generates a message,
optionally pays to remove the watermark, and the card is shared with the recipient
(and optionally delivered via WhatsApp).

- [Architecture](./architecture.md) — monorepo layout, stack, request flow, data storage status
- [API Reference](./api.md) — every route actually implemented in `artifacts/api-server`
- [Environment Variables](./environment.md) — every env var actually read by the code
- [Integrations & Background Jobs](./integrations-and-jobs.md) — Gemini, Razorpay, WhatsApp, cron jobs

Root-level `replit.md` (repo root, not in `docs/`) contains the Replit-specific
run/operate commands and is the canonical place for that — see there for exact
`pnpm --filter ...` commands. It still has several unfilled placeholder sections
("Where things live", "Architecture decisions", "Product", "Gotchas") that this
`docs/` set fills in with verified detail.

## What this app does NOT have yet (verified)

These are called out in more detail in the linked docs, but worth stating up front
since it affects how you read everything else here:

- No database tables are defined (`lib/db/src/schema/index.ts` is an empty stub).
  Every route currently reads/writes plain in-memory arrays.
- The OpenAPI spec (`lib/api-spec/openapi.yaml`) only documents `/healthz`. The five
  real product routers (`cards`, `payment`, `ai`, `track`, `whatsapp`) are hand-written
  Express routers, not spec'd or codegen'd.
- Photo upload in the create flow is client-side only (`URL.createObjectURL`) — nothing
  is uploaded to any storage backend.
- The "voice note" and "PDF download" add-ons in the create flow are UI-only placeholders
  that always stay off and just show an upgrade nudge.
